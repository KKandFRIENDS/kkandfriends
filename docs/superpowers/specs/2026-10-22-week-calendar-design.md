# 이번 주 체크 포인트 (Week Calendar) 설계

작성일: 2026-10-22 · 상태: 검토 대기 (KK 승인 전, 구현 금지)

## 1. 목적

독자가 "이번 주에 무엇을 지켜봐야 하나"를 한눈에 보는 발표·일정 섹션을 사이트에 추가한다.

- 홈에는 이번 주 일정 3~5줄 요약 카드, 전체는 공개 페이지 `/week`.
- 숫자와 날짜는 모두 출처를 붙인다. 출처 없는 항목은 화면에 나오지 않는다.
- 종목을 찍지 않는다. 확신을 팔지 않는다 (기존 원칙).

KK 결정 (2026-10-22 대화): 공개 / 홈 요약 + `/week` / 한국 우선 / 연간 일정 파일은 Claude 초안 → KK 승인 PR.

## 2. 사실 확인 결과 (2026-10-22, 실제 호출)

| 소스 | 미래 일정을 주는가 | 근거 |
|---|---|---|
| OpenLaw (법제처) | **예** | 시행예정 법령은 시행일이 확정된 미래 날짜. 이미 `lib/stats/openlaw.js`, 08:30 법령 감시가 사용 중 |
| ECOS (한국은행) | **확인 못 함** | 100대 지표·통계표 목록은 정상. 짐작한 주소(`ReleaseSchedule`)는 503이었으나 이는 "없다"의 증거가 아님 |
| KOSIS (통계청) | **확인 못 함** | 이미 발표된 값만 확인. 공표 일정 API는 시도하지 않음 |
| DART (금감원) | 확인 못 함 | 공시는 제출된 것만. 예정성 공시는 종목 이름이 따라붙어 이번 범위에서 제외 |

결론: 1차 구현은 OpenLaw(자동) + 공식 달력을 옮겨 적은 일정 파일(반자동)로 간다. ECOS·KOSIS가 일정 API를 주는 것이 나중에 확인되면 해당 항목만 파일에서 자동 수집으로 옮긴다.

## 3. 범위

포함
- `/week` 공개 페이지, 홈 요약 카드
- 일정 파일 `data/week-calendar/<연도>.json` + 검증
- 법령 시행예정 칸 (OpenLaw, 요청 시 조회 + CDN 캐시)
- 사이트맵·robots 반영

제외 (이번에 하지 않음)
- VPS 예약 작업, 텔레그램 알림 (Vercel cron 0개 원칙 유지, 일정 파일은 사람이 확인하는 PR)
- 종목별 실적 발표, 공시 상세
- 라운지(멤버 전용) 노출, LinkedIn·Instagram·Facebook 자동 공유
- ECOS·KOSIS 일정 자동 수집 (확인 후 별도 작업)

## 4. 데이터

### 4.1 일정 파일

`data/week-calendar/2026.json` (연도별 한 파일)

```json
{
  "year": 2026,
  "items": [
    {
      "id": "2026-11-27-bok-mpc",
      "date": "2026-11-27",
      "time": "09:00",
      "region": "kr",
      "title": "한국은행 금융통화위원회",
      "note": "기준금리를 올리거나 내리거나 그대로 둘지 정하는 회의. 결과는 당일 발표.",
      "source": { "name": "한국은행 금융통화위원회 일정", "url": "https://..." },
      "verifiedAt": "2026-10-22"
    }
  ]
}
```

필드 규칙
- `date`: `YYYY-MM-DD` (KST 날짜). `time`: 선택, `HH:MM` KST. 시각을 모르면 생략하고 "시각 미정"으로 표시하지 않는다.
- `region`: `kr` | `us` | `global`
- `title`, `note`: 한 줄. 약자는 처음 나올 때 풀어 쓴다 (풀어쓰기 규칙). em dash 금지. 종목명 금지(2026-10-27부터 기업 실적 발표 날짜 항목만 예외, KK 결정).
- `source.url`: `https://` 필수. 공식 기관 달력 페이지만 (한국은행, 통계청, Fed, BLS 등).
- `verifiedAt`: 해당 항목을 출처에서 직접 확인한 날. 없으면 무효.

### 4.2 법령 칸

OpenLaw에서 자본시장법 계열 시행예정 버전을 읽고, 시행일이 보여줄 주(週) 안에 드는 것만 표시한다. 기존 `fetchLawWatch` 결과에서 시행일을 뽑는 순수 함수를 `lib/stats/openlaw.js`에 추가한다 (정확한 시그니처는 구현 계획에서 기존 코드를 읽고 정한다). 이 칸의 출처는 법제처로 고정한다.

## 5. "이번 주"의 정의

월요일~일요일 (KST). 토·일에는 **다음 주**를 보여준다 (이번 주는 이미 끝났으므로). 이 규칙은 순수 함수 `weekWindow(now)`로 분리해 테스트한다. (가정입니다. 다르게 하고 싶으시면 검토 때 알려 주세요.)

## 6. 서빙 구조

- Vercel 함수는 12개 상한이다 (`api/desk.js` 머리말). **새 `api/*.js` 파일을 만들지 않는다.** `api/desk.js`에 `view=week`를 추가하고 `vercel.json`에 `/week` → `/api/desk?view=week` 리라이트를 넣는다.
- HTML 렌더링은 `lib/week-render.js` (순수 함수, 저장소·네트워크 접근 없음). 일정 로드·검증은 `lib/week-calendar.js`.
- `/week`: 서버에서 완성된 HTML을 내려준다 (검색엔진 색인 가능). 같은 view가 `format=json`도 지원한다.
- 홈 카드: 정적 `index.html`에 빈 슬롯을 두고, 로드 후 `format=json`을 한 번 읽어 그린다. 실패하거나 일정이 없으면 카드를 숨긴다. 홈 성능 테스트(`tests/performance.test.mjs`)와 기존 4초 지연 규칙을 깨지 않도록 렌더 차단 요청을 추가하지 않는다.
- 캐시: 정상 `s-maxage=3600`, 법령 조회 실패로 일부만 나갈 때는 `s-maxage=60`.
- 사이트맵: `lib/feeds.js` `STATIC_PAGES`에 `/week` 추가. `robots.txt`는 막지 않는다.
- 디자인: 기존 `typography.css`와 사이트 글꼴 기준을 따른다 (Pretendard 본문, 제목만 serif). 폰 폭에서 가로 스크롤 없음.

## 7. 실패 처리

| 상황 | 동작 |
|---|---|
| 법령 조회 실패 / `OPENLAW_OC` 없음 | 법령 칸만 "지금 확인할 수 없습니다" 표시. 지난주 내용을 재사용하지 않음. 60초 캐시 |
| 이번 주 일정 0건 | "이번 주 예정된 주요 일정이 없습니다" (일정 파일이 있는 연도일 때) |
| 해당 연도 파일 없음 | "올해 일정이 아직 준비되지 않았습니다". 홈 카드는 숨김 |
| 일정 파일 검증 실패 | 테스트가 CI에서 막는다 (배포되지 않음). 런타임에서는 검증 실패 항목만 제외 |

교훈 적용: 설정 누락을 성공으로 보고하지 않는다. 사용자에게 "비어 있음"과 "확인 실패"를 다른 문구로 보여준다.

## 8. 일정 파일 관리 절차

1. Claude가 공식 달력 페이지를 직접 읽고 `data/week-calendar/<연도>.json` 초안을 PR로 올린다.
2. PR 설명에 "확인한 항목 / 확인하지 못해 제외한 항목"을 나눠 적는다. 확인 못 한 항목은 파일에 넣지 않는다.
3. KK가 한 번 보고 병합한다.
4. 연말(12월)에 다음 해 파일을 준비한다. `CLAUDE.md`에 이 절차와 날짜를 한 줄 기록한다.

한계 (확인 필요): 이 컨테이너에서 한국은행·통계청·Fed·BLS 달력 페이지에 접근되는지 아직 모른다. 접근이 막히면 KK가 해당 페이지 링크나 PDF를 주셔야 한다. 미국 일정 중 접근 못 한 것은 넣지 않는다.

## 9. 테스트

- `tests/week-calendar.test.mjs`: 일정 파일 스키마 (필수 필드, `https` 출처, `verifiedAt`, 날짜 형식, em dash 금지, id 중복 없음)
- `weekWindow`: 평일/토/일/월 경계, 연말·연초 경계
- 렌더: 항목 정렬, 빈 주, 법령 실패 문구, 홈 카드 HTML, 이스케이프
- `view=week` 핸들러: 가짜 저장소로 200/JSON/캐시 헤더
- 기존 `tests/discoverability.test.mjs`, `tests/performance.test.mjs`, `tests/typography.test.mjs`, `tests/design-system-consistency.test.mjs`가 계속 통과

## 10. 확인 필요 (구현 전·중에 처리)

1. Vercel 환경변수에 `OPENLAW_OC`가 있는가. 없으면 KK가 Vercel 설정에 직접 추가 (채팅에 값 붙이지 않기).
2. Vercel에서 OpenLaw HTTPS가 되는가. 이 컨테이너에서는 `http://www.law.go.kr`가 필요했다 (`OPENLAW_BASE`). Vercel 배포 후 첫 호출로 확인.
3. 공식 달력 4곳(한국은행, 통계청, Fed, BLS) 접근 가능 여부.
4. 1차 일정 파일의 범위: 2026년 11~12월분 + 이미 공개된 2027년분.
5. ECOS·KOSIS 일정 API 존재 여부 (별도 조사, 이번 구현과 분리).
